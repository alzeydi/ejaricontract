# «Contract check» — бесплатная проверка договора для трафика с DEWA-гайда

План (Фаза 4): только проектирование, ничего не реализовано. Подготовлено 21.10.2026.

## Зачем

`/guide/dewa-premises-number` приносит 55% поисковых кликов. Человек ищет номер DEWA и уходит, как только его нашёл, — до генератора доходят единицы. При этом договор у него обычно уже есть (от агента или арендодателя). Отсюда идея: предложить бесплатную проверку этого договора, найти в нём проблемы и продать исправление через генератор за `CONTRACT_PRICE_AED`.

## Флоу

1. CTA на `/guide/dewa-premises-number` ниже сгиба, сразу после блока с ответом:
   > **Found your premise number? Make sure your contract won't be rejected.**
   > Upload your tenancy contract — AI checks it against Ejari rules in 60 seconds. Free.
   > **[Check my contract →]**

   События: `upsell_shown` / `upsell_click {placement: 'dewa_contract_check'}`. Блок статичный и не влияет на CLS. Title, H1, meta и schema не меняются.
2. Страница `/contract-check`. Пользователь загружает договор (PDF или фото, 1–3 страницы), опционально — Title Deed для сверки. Проверку Turnstile и лимит 5 извлечений в день берём те же, что у `/extract`.
3. `POST /check`: OCR договора (Haiku, новый промпт `TENANCY_CONTRACT`, все поля DLD) → движок правил → JSON со списком проблем.
4. Результат: «X проблем найдено». Каждая проблема — с уровнем серьёзности (🔴 отклонят / 🟠 риск / 🟢 ок), полем и подсказкой, как исправить.
5. CTA: **«Fix it in the generator — preview free»**. Поля, извлечённые из договора, переносятся в `localStorage` под тем же ключом, что использует генератор (`ejari_form`), и человек попадает на `/#start` сразу на экран проверки полей. Дальше — превью и оплата по уже готовому флоу.

## Правила (по списку отказов из `/guide/tenancy-contract-dubai`)

| Причина отказа (из гайда) | Автопроверка | Как |
|---|---|---|
| Не форма DLD Unified Tenancy Contract | ✅ | OCR-классификация: заголовок «TENANCY CONTRACT / عقد إيجار» и шапка DLD. Если формы нет — 🔴 |
| Пустые обязательные поля | ✅ | Тот же `REQUIRED_FIELDS`, что в генераторе |
| Неверный формат Emirates ID / DEWA / Makani | ✅ | Тот же `validate_contract()` |
| Нет Makani (обязателен для новых регистраций) | ✅ | 🟠 если пусто (в генераторе Makani сейчас необязателен — см. «Открытые вопросы») |
| Даты: конец раньше начала, срок не 12 месяцев | ✅ | `_parse_date`; нестандартный срок — 🟠 |
| Сумма договора ≠ аренда × срок | ✅ | Та же формула, что `recalc()` в генераторе |
| Имя владельца / поля объекта не совпадают с Title Deed | ✅ при загруженном Title Deed | Посимвольное сравнение после нормализации: регистр, пробелы, «Apt»/«Apartment». Различие — 🔴 с обоими вариантами написания |
| Просроченный Emirates ID | ⚠️ частично | Только если загружены сами ID (в договоре срока нет). Иначе — напоминание 🟢 |
| Аренда выше лимита RERA (продления) | ⚠️ частично | Если указана прошлая аренда, используем калькулятор `/tools/rent-increase-calculator`. Индекс RERA не автоматизируем — показываем ссылку |
| Пересечение дат с прошлым Ejari | ❌ | Нужна база DLD — только напоминание |
| Ксерокопии подписей | ❌ | По скану не определяется надёжно — только напоминание |

Правила вынести в данные (`CHECK_RULES`: id, severity, message, fix_hint), чтобы проверка и тесты использовали один источник.

## Что нового

- Промпт `TENANCY_CONTRACT`: многостраничный PDF, все поля DLD + флаг «это форма DLD». `max_tokens` около 800.
- Движок правил + сравнение с Title Deed.
- Страница `/contract-check`: загрузка → список проблем → CTA. Без индексации до проверки качества, потом — отдельная SEO-страница под запросы «ejari rejected», «check tenancy contract».
- События: `contract_check_started`, `contract_check_completed {issues_red, issues_amber}`, `contract_check_fix_click`.

## Оценка трудозатрат

| Задача | Часы |
|---|---|
| Промпт `TENANCY_CONTRACT` + отладка на 10–15 реальных договорах | 3–4 |
| `CHECK_RULES` + движок + сравнение с Title Deed | 3–4 |
| `/check` endpoint (лимит, Turnstile, стоимость) | 1 |
| Страница результата (375 / 1280, EN) | 3 |
| Перенос полей в генератор | 1 |
| CTA на DEWA-гайде (EN + AR) | 1 |
| Тесты (правила, endpoint, перенос) + браузерный прогон | 2–3 |
| **Итого** | **14–17 ч (~2 рабочих дня)** |

Стоимость OCR: договор на 3 страницы ≈ 6–8 тыс. входных токенов на Haiku 4.5 ≈ $0.007–0.01 за проверку. При лимите 5 в день на посетителя — пренебрежимо. Если перейти на `claude-haiku-5-5` ($0.10 / $0.50 за 1M), стоимость упадёт ещё примерно в 10 раз, но точность OCR сначала нужно проверить.

## Как мерить

- CTR CTA на DEWA-гайде: цель ≥ 3% от `page_view` гайда.
- Доля проверок, где найдена хотя бы одна 🔴/🟠 проблема.
- Переходы `contract_check_fix_click` → `purchase`. Это главная метрика.

## Открытые вопросы

1. **Makani.** Гайд говорит «required for new registrations», а генератор сейчас разрешает пустой Makani (по ТЗ — только проверка формата). Решить: делать его обязательным для новых договоров (не продлений)?
2. **Хранение.** Договор, как и документы, не хранится — обрабатывается в памяти. Политика конфиденциальности это уже покрывает.
3. **Арабская версия** `/ar/guide/dewa-premises-number`: CTA сразу или после проверки английского?
